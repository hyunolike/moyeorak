# 모여락 Brand v2 — 합류점

> 서로의 시간을, 하나의 약속으로.

서비스 이름은 **모여락**, 새로운 비서 캐릭터의 이름은 **마주**다. 2026년 10월 30일 리뉴얼 기획의 제품 역할을 바탕으로 제작했다. 이번 의뢰의 완전 신규 브랜드 지시를 우선해, 기획서에 남아 있는 기존 파란색과 구름 실루엣 유지 조항은 적용하지 않았다. 이전 로고와 캐릭터의 패스, 색상, 소품은 재사용하지 않았다.

## 1. 브랜드 전략

### 포지셔닝

모여락은 친구들의 가능한 시간과 출발지를 모아 **받아들일 만한 약속 한 가지로 정리하는 조율 비서**다. 20~30대 친구 모임에서 누군가 혼자 맡았던 총무 일을 덜어 준다. 카카오톡 링크로 들어와 가능한 시간을 말하면, 모여락이 시간표를 채우고 공평하게 만날 곳을 제안한다. 마지막 결정은 사람이 한다.

브랜드가 기억되어야 하는 순간은 세 번이다. 링크를 열었을 때의 가벼운 시작, 응답을 기다리는 동안의 차분한 안내, 단톡방에 돌아온 확정 카드다. 세 순간에 같은 얼굴과 말투가 이어진다.

### 세 가지 키워드

| 키워드 | 제품에서 하는 일 | 시각 언어 |
|---|---|---|
| 합류 | 각자의 조건을 같은 약속으로 연결한다 | 노선의 꺾임, 종점, 밝은 공통 구간 |
| 공평 | 이동시간과 가능한 시간을 함께 살핀다 | 정면의 균형 잡힌 얼굴, 같은 크기의 두 눈 |
| 가뿐함 | 한 문장으로 입력하고 한 번 확인한다 | 짧은 문장, 단단한 면, 한 화면의 주된 행동 하나 |

### 말투

짧은 해요체를 쓴다. 현재 확인한 사실을 먼저 말하고 다음 행동을 제안한다. 기다리는 사람에게 죄책감을 주지 않는다. 모르는 값이나 외부 서비스 오류를 감추지 않는다. 제안과 확정을 구분하고, 사람의 확인을 받기 전에 완료됐다고 말하지 않는다.

| 상황 | 마주의 말 |
|---|---|
| 자연어 입력을 해석한 뒤 | “평일 저녁으로 담았어요. 수요일은 뺐어요. 맞는지 봐 주세요.” |
| 응답 대기 | “3명이 응답했어요. 서연님 기다리는 중” |
| 제안 | “일요일 2시, 홍대입구역은 어때요? 4명 모두 가능해요.” |
| 확정 후 | “일요일 2시, 홍대입구역으로 정했어요. 단톡방에 알려 주세요.” |
| 외부 서비스 실패 | “장소 정보를 불러오지 못했어요. 잠시 후 다시 불러와 주세요.” |

“서연님만 아직이에요!”, “제가 완벽하게 정했어요”, “AI가 최적화했어요” 같은 재촉, 과장, 기술 과시는 쓰지 않는다. 무조건적인 애교나 반복되는 감탄사도 쓰지 않는다.

### 느껴지면 안 되는 것

친구를 관리하는 회사용 출결 도구, 예약이나 결제를 대신하는 서비스, 만능 AI 챗봇, 어린이용 캐릭터 상품처럼 느껴지면 안 된다. 화면 곳곳에 캐릭터를 반복하거나 발광, 반짝이, 마법봉으로 AI를 표현하지 않는다. 이전의 파란 꽃구름과 장갑, 신발, 풍선 같은 팔다리 실루엣으로 돌아가지 않는다.

## 2. 세 방향 탐색

### A. 합류점 — 선택

[SVG 시트](exploration/01-junction.svg) / [탐색 메모](exploration/01-junction.md)

지하철 노선이 합쳐지는 공통 구간을 역명판 모양으로 만들었다. 얼굴의 밝은 캡슐은 함께 가능한 시간과 중간지점이고, 두 눈은 그곳에 도착한 사람이다. 팔 끝은 노선의 종점이다. 오른쪽 아래의 잘린 모서리는 다음 구간으로 이어지는 방향을 남긴다. 심벌, 장소 안내, 시간표, 공유 카드에 같은 문법을 적용할 수 있다.

### B. 겹친 한 칸

[SVG 시트](exploration/02-overlap.svg) / [탐색 메모](exploration/02-overlap.md)

두 시간표가 겹치는 노란 영역을 얼굴로 만든다. 겹치는 시간이 곧 로고의 중심이므로 일정 입력 기능은 즉시 설명된다. 보라색의 두 레이어와 작은 얼굴은 32px에서 분리가 어렵고, 장소 조율과 이동시간의 공평함까지 설명할 연결 고리는 약하다. 시간만 투표하던 도구로 인식될 수 있어 선택하지 않았다.

### C. 우리 한자리

[SVG 시트](exploration/03-table.svg) / [탐색 메모](exploration/03-table.md)

세 의자가 원탁을 둘러싸는 환대의 장면이다. 모임의 자리를 미리 준비한다는 정서가 자연스럽다. 다만 작은 크기에서 의자가 꽃잎처럼 보이고 식당 예약 서비스로 읽힐 여지가 있다. 이전 꽃구름과 실루엣의 거리를 벌린다는 조건에도 A보다 약해 선택하지 않았다.

### 선택 이유와 남겨 둔 경계

합류점은 **시간의 공통 구간과 이동의 중간지점**을 함께 설명한다. 복잡한 겹침 없이 한 개의 덩어리로 읽히고, 팔과 다리를 덜어 내면 앱 아이콘이 된다. 두 눈만 남겨도 같은 얼굴이라 큰 일러스트와 16px 파비콘 사이의 연결이 유지된다.

역명판에서 출발했지만 실제 교통기관의 노선색, 로고, 역 표지판은 모사하지 않았다. 서비스가 지하철 전용으로 보이지 않도록 차량, 승차권 문구, 노선 번호는 캐릭터에 붙이지 않는다. 노선 도형은 ‘각자의 조건이 합쳐진다’는 설명이 필요한 장면에만 쓴다.

## 3. 색상

이전 파랑과 청록 대신 **홍시색, 짙은 녹색, 신호 노랑**을 쓴다. 홍시색은 작게 보여도 따뜻한 얼굴로 기억된다. 짙은 녹색은 CTA와 읽을 수 있는 정보를 맡고, 노랑은 비서의 발화와 제안을 구분한다. 세 색은 모두 면으로 사용한다. 캐릭터 안에 그라디언트는 넣지 않는다.

성공과 응답 완료, 미응답, 오류는 색만으로 전달하지 않는다. 체크 표시와 “응답 완료”, “기다리는 중”, 원인과 재시도 버튼을 함께 쓴다. 장식용 구분선을 필수 입력 테두리로 쓰지 않는다.

## 4. 타이포그래피와 워드마크

제품 UI는 **Pretendard**를 사용한다. 제목 28/36px 700, 큰 메시지 38/50px 700, 본문 16/25px 400, 버튼 17/24px 600, 보조 정보 14/21px 400을 기본으로 한다. 제목 자간은 -0.03em 이내, 본문은 0에서 시작한다. 작은 상태 라벨은 12px까지 허용하며 핵심 행동과 본문에는 쓰지 않는다.

한글 워드마크는 기존 폰트를 변환한 것이 아니다. ㅁ의 빈 사각형, ㅇ의 캡슐, ㄹ의 꺾임을 직접 설계해 모여락 세 글자를 만들었다. 기본 획은 10px이고 ‘여’의 ㅇ에는 내부 공간을 확보하는 9px 광학 보정이 있다. 직선과 둥근 모서리의 비율을 심벌과 맞췄다. Pretendard 본문 옆에서 로고가 별개의 글꼴처럼 경쟁하지 않게 짧고 단단한 밀도로 그렸다.

영문 `moyeorak`도 별도로 그렸다. m의 두 합류 곡선, o의 순환 구간, y와 k의 갈림길을 8px 둥근 획으로 설계하고 **닫힌 벡터 윤곽선으로 확장**했다. 한글을 영문으로 대체할 때도 서비스 이름의 표기는 소문자 `moyeorak`을 쓴다. 대문자 변형이나 별도 이탤릭체를 만들지 않는다.

최종 로고 파일에는 `<text>`, 외부 폰트, 래스터, 실행 스크립트가 없다. 샘플 UI와 OG 이미지의 한국어는 macOS의 **Apple SD Gothic Neo Regular/Bold**로 조판한 뒤 CoreText로 윤곽선을 추출했다. 따라서 rsvg 렌더링에 한국어 폰트 설치가 필요하지 않다. `og-template.svg`의 호스트와 날짜 슬롯 두 개만 편집 가능한 텍스트다. 폰트 파일은 포함하지 않았다. HTML 보드는 로컬 Pretendard가 있으면 사용하고 Apple SD Gothic Neo로 대체한다.

## 5. 로고 사용

[로고 구성 도면](logo/construction.svg)

### 조합과 여백

기본은 [가로 조합](logo/lockup-horizontal.svg)이다. 좁은 정사각형 공간에는 [세로 조합](logo/lockup-vertical.svg), 앱과 아바타에는 [심벌](logo/symbol.svg)을 쓴다. 문장 속 서비스 이름은 일반 텍스트로 쓰되, 브랜드 서명 자리에 워드마크를 다시 타이핑하지 않는다.

심벌의 160px 원본에서 **x = 밝은 캡슐 높이 48px의 절반 = 24px**다. 실제 칠해진 외곽부터 다른 내용까지 사방에 x 이상을 비운다. 배경 면은 여백에 포함하지 않는다. 내장된 SVG 아트보드의 빈 공간만으로 보호 여백이 모두 확보되는 것은 아니므로 배치할 때 추가한다.

가로 조합은 심벌 0.6배, 한글 0.9배다. 심벌과 글자의 실제 면 사이 간격은 약 34px로, 같은 배율에서 x=14.4px보다 넓다. 세로 조합은 심벌 아래에 글자를 중앙 정렬하고 실제 면 사이에 24px를 둔다. 조합 안의 상대 비율을 바꾸지 않는다.

### 최소 크기

| 에셋 | 최소 화면 크기 | 권장 |
|---|---:|---:|
| 가로 조합 | 너비 120px | 144px 이상 |
| 세로 조합 | 너비 88px | 120px 이상 |
| 한글 워드마크 | 너비 80px | 112px 이상 |
| 영문 워드마크 | 너비 132px | 165px 이상 |
| 독립 심벌 | 24px | 32px 이상 |
| 얼굴 아바타 | 32px | 32~48px |
| 전신 캐릭터 | 96px | 160~240px |
| 전용 파비콘 | 16px | 제공한 16/32px PNG 사용 |

파비콘은 단순 축소본이 아니다. 입과 외곽선을 없애고 16px 그리드에서 눈을 각각 2×4px로 보정했다. 16px에서는 표정의 구별보다 브랜드 식별을 우선한다.

### 바탕과 금지 사항

밝은 바탕에는 원색 가로 조합, 어두운 바탕에는 [단색 흰색](logo/lockup-horizontal-mono-white.svg)을 우선한다. 인쇄와 단색 표현은 [단색 검정](logo/lockup-horizontal-mono-black.svg)을 사용한다. 단색 파일의 캡슐 구간은 흰 페인트가 아니라 실제 뚫린 면이라 바탕이 비친다.

로고를 늘이거나 기울이지 않는다. 심벌 안에 달력 숫자, 사용자 이니셜, 반짝이를 넣지 않는다. 심벌과 글자 사이에 슬로건을 끼워 넣지 않는다. 워드마크의 한 글자만 다른 색으로 강조하지 않는다. 회색과 복잡한 사진 위에 직접 놓지 말고 충분한 단색 바탕을 마련한다. 캐릭터에 그라디언트, 입체 음영, 장갑, 신발을 더하지 않는다.

## 6. 캐릭터 ‘마주’

### 이름과 성격

**마주**는 친구들이 마주 앉는 순간과 서로의 조건을 마주 보는 태도에서 왔다. “마주가 제안해요”, “마주에게 맡겨요”처럼 짧게 부를 수 있다. 모여락이라는 서비스 이름과 구별되어, 누가 말하는지 명확해진다. 이전 캐릭터와 완전히 새 관계를 만들기 위해 ‘모락이’라는 이름을 이어 쓰지 않았다.

마주는 모임의 작은 역장이다. 모두의 출발점을 먼저 살피고, 기다리는 동안 현재 상황을 알려 준다. 결정을 독촉하는 총무보다 옆에서 정리하는 친구에 가깝다. 작은 성취에는 기뻐하지만 오류에서 울거나 사용자를 탓하지 않는다.

### 기하학 구조

[캐릭터 구성 도면](character/construction.svg)

| 항목 | 기준 |
|---|---|
| 공통 원본 | 240×240px, 정면 기준 |
| 그리드 | 기본 8px, 보조 4px, 곡선과 눈의 광학 보정은 정수 px |
| 얼굴 겸 몸 | 로컬 160px 좌표에서 (16,16)~(144,144), 128×128px |
| 원본 배치 | 몸을 (40,28)에 이동, 실제 면은 (56,44)~(184,172) |
| 모서리 | 반지름 32px, 오른쪽 아래만 32px 직선으로 절단 |
| 공통 구간 | 88×48px, 반지름 24px |
| 기본 눈 | 각각 10×24px, 두 눈 중심 사이 34px |
| 외곽선과 노선 팔 | 8px, 둥근 끝과 둥근 연결 |
| 입 | 6px, 눈과 같은 잉크색 |
| 종점 | 반지름 9px, 노랑 면과 8px 잉크선 |
| 발 | 20×38px, 반지름 10px, 단색 종단 |
| 배경 대응 | 전신에 바탕색 4px 외부 키라인. 다크에서 팔과 발의 외곽 보존 |

몸과 캡슐, 팔의 정수 좌표를 공통으로 유지한다. 기본 외곽선은 8px, 표정의 보조선은 6px이며 임의로 얇게 만들지 않는다. 전신의 외부 키라인은 새 색이 아니라 얼굴과 같은 낮 바탕색이다. 전신에 쓰는 면은 홍시, 낮 바탕, 신호 노랑 세 색과 잉크 한 색뿐이다. 얼굴 전용 아바타는 키라인 없이 홍시 면으로 바탕과 분리한다.

캐릭터와 심벌은 같은 원형을 쓰되 동일 파일을 무조건 축소하지 않는다. 심벌은 입과 잉크 외곽선을 덜고, 아바타는 팔과 발을 덜고 표정은 남긴다. 팔다리의 각도를 유지하며 자세를 바꾼다. 얼굴과 몸을 따로 잡아 늘이거나 머리에 추가 장식을 붙이지 않는다.

### 여섯 표정과 사용 규칙

| 파일 이름 | 의미 | 화면 |
|---|---|---|
| `default` | 편안한 정면 | 일반 안내, 기본 아바타 |
| `thinking` | 위를 보는 짧은 눈과 작은 원형 입, 손을 대는 자세 | 조건 해석, 이동시간 비교 |
| `waiting` | 가로로 쉰 눈과 낮춘 팔 | 응답 대기, 진행 현황 |
| `happy` | 웃는 눈과 들어 올린 두 팔 | 사용자가 확정한 직후 |
| `sorry` | 안쪽으로 올라간 눈썹과 작은 찡그린 입 | 외부 API 실패, 재시도 안내 |
| `guide` | 윙크와 한쪽 팔의 종점 | 첫 방문, 입력 방법 설명 |

모든 전신은 240×240px, 얼굴 원본은 160×160px 정사각형이다. **얼굴은 32px에서도 두 눈과 공통 구간이 분리된다.** 생각 중과 기다림은 눈의 방향과 입을 다르게 그렸다. 표정만으로 진행 상태를 전달하지 말고 항상 짧은 문장을 붙인다. 한 화면에서 말하는 얼굴은 하나만 사용한다.

### 동작

`character/motion/thinking-loop.svg`는 **1.6초** 주기로 몸이 4px 이내에서 오르내리고 세 개의 종점 신호가 순서대로 밝아진다. `prefers-reduced-motion: reduce`에서는 모든 키프레임이 정지하고 점이 모두 보인다. 실패, 대기 상태에서 관심을 끄는 반복 동작은 쓰지 않는다. 루프가 완료율이나 남은 시간을 의미하는 것처럼 사용하지 않는다.

## 7. 제품에서 쓰는 법

### 비서의 발화와 제안

마주의 말풍선은 신호 노랑 면, 왼쪽 아래의 짧은 꼬리, ‘마주의 한마디’ 라벨로 식별한다. 색을 못 봐도 발화 주체가 드러난다. 제안 배지는 같은 노랑을 쓴다. 사용자가 누르는 주요 버튼은 숲색이다. 캐릭터 얼굴을 누르는 동작 대신 명시적인 텍스트 버튼을 둔다.

### 상태

빈 화면은 ‘모임 만들기’로 이어진다. 오류는 “장소 정보를 불러오지 못했어요”처럼 실패한 범위를 밝히고 ‘다시 불러오기’를 제공한다. 로딩은 ‘각자의 이동시간을 비교하고 있어요’처럼 실제 수행 중인 일만 말한다. 마주의 미안한 표정이 오류 원인과 복구 방법을 대신하지 않는다.

| 파일 | 목적 |
|---|---|

제안 카드의 긴 날짜와 장소는 한 줄에 압축하지 않고 날짜, 시간, 역명을 나눴다. SVG 접근성 제목에는 원래의 전체 문장을 남겼다. 목업의 노선도는 브랜드 적용을 보여 주는 도식이며 실제 경로나 추천 결과 데이터가 아니다. 이 파일들은 고정 화면 디자인 참고용이고 작동하는 앱은 아니다. 실제 화면에서는 사용자 입력, 응답 인원, 이동시간에 따라 문구와 데이터가 바뀌어야 한다.

### 앱 아이콘과 공유 카드

`icon.svg`는 512px 기본 원본이다. `maskable.svg`는 배경을 끝까지 채우고, 모든 중요한 심벌을 중심 (256,256), 반지름 204.8px의 안전 원 안에 배치했다. 마스커블 파일에는 바깥쪽 둥근 모서리를 미리 자르지 않는다. Apple touch 아이콘과 표준 아이콘은 제공한 별도 PNG를 사용한다.

`og-template.svg`는 1200×630px이다. `host-slot`의 `{호스트}님의 모임`, `date-slot`의 `{날짜 및 시간}`을 XML 이스케이프한 문자열로 치환한다. 호스트 이름은 최대 한글 6자까지 한 줄을 권장하며, 길면 2줄로 재배치하거나 UI의 말줄임 규칙을 적용한다. 템플릿 폰트의 첫 후보는 Apple SD Gothic Neo다. Linux 서버에서는 Pretendard 또는 Noto Sans KR을 설치하고 결과를 다시 확인해야 한다. 샘플은 “현호님의 모임” / “11월 1일 일요일 오후 2시”로 윤곽선 처리되어 폰트 없이도 동일하게 렌더링된다.

## 8. 제작과 검증

모든 결과물과 제작 코드는 이 폴더 안에 있다. `reference/`와 `design/moraki/`에는 쓰지 않았으며 커밋하지 않았다. 세 탐색안의 한 문단 메모도 각 SVG 옆에 두었다.

macOS의 Swift/CoreText와 `rsvg-convert`를 사용한다. 재생성 명령은 저장소 루트 기준 다음과 같다.

```sh
python3 design/brand-v2/tools/build.py
python3 design/brand-v2/tools/verify.py
```

`build.py`는 SVG 원형과 UI 문구를 조합하고, Swift가 글자와 영문 로고 획을 닫힌 벡터로 바꾼다. `rsvg-convert`가 요청된 PNG 11개를 만든다. 생성된 로고는 이미 윤곽선이므로 사용 시 Swift가 필요 없다. Swift 바이너리와 모듈 캐시는 재생성 가능하여 납품 파일에서 제외한다.

검증은 모든 SVG의 파싱과 `viewBox`, 내장 래스터 및 외부 참조 부재, 로고의 라이브 텍스트 부재, 전신과 얼굴 캔버스의 일치, 모든 SVG의 실제 rsvg 렌더 성공, 확장 캔버스에서의 외곽 잘림, PNG 11개의 정확한 크기, 마스커블 심벌의 원형 안전 영역, 허용 텍스트 조합의 AA 대비, HTML 로컬 링크를 확인한다. 자동 결과는 [verification.json](qa/verification.json)에 남긴다. 한 장 보드와 세 화면, 공유 카드, 소형 아이콘은 별도로 눈으로 확인했다.

`index.html`을 열면 밝고 어두운 바탕의 로고, 표정과 32px 아바타, 화면, 상태, 아이콘, 탐색안과 구성 도면을 볼 수 있다. 한 번에 공유할 때는 `brand-board.png`를 사용한다.
