# 모여락 Brand v3 — 합류점, 마주

> 서로의 시간을, 하나의 약속으로.

v2에서 콘셉트와 이름, 원색, 워드마크를 이어받고 캐릭터, 색 체계, 디자인 시스템을 다시 만들었다. 무엇을 왜 바꿨는지는 [REVIEW.md](REVIEW.md), 컴포넌트 명세는 [components/components.md](components/components.md), 토큰은 [tokens.css](tokens.css)와 [tokens.json](tokens.json)에 있다. 전체 모습은 [index.html](index.html) 또는 [brand-board.png](brand-board.png).

## 1. 전략 요약

모여락은 친구들의 가능한 시간과 출발지를 모아 받아들일 만한 약속 하나로 정리하는 조율 비서다. 마지막 결정은 사람이 한다.

| 키워드 | 제품에서 | 시각 언어 |
|---|---|---|
| 합류 | 각자의 조건을 같은 약속으로 연결한다 | 노선이 만나는 구간, 밝은 공통 캡슐 |
| 공평 | 이동시간과 가능한 시간을 함께 살핀다 | 정면의 균형 잡힌 얼굴, 같은 크기의 두 눈 |
| 가뿐함 | 한 문장으로 입력하고 한 번 확인한다 | 짧은 문장, 한 화면에 주요 행동 하나 |

말투는 짧은 해요체. 확인한 사실을 먼저 말하고 다음 행동을 제안한다. 기다리는 사람에게 죄책감을 주지 않고, 사람이 확인하기 전에 확정됐다고 말하지 않는다. 회사용 출결 도구, 만능 AI 챗봇, 어린이용 캐릭터 상품처럼 느껴지면 안 된다. 반짝이, 마법봉, 발광으로 AI를 표현하지 않는다.

## 2. 캐릭터 마주

### 얼굴 구조

역명판 모양 몸(홍시) 안에 넓고 낮은 크림 캡슐(#FFF1DA)이 있고, 얼굴 요소는 전부 그 안에 있다. 둥근 눈 두 개(각각 작은 하이라이트), 입, 연한 볼(#FFBBA8). 캡슐이 "모두가 되는 시간과 중간지점", 두 눈이 "거기 도착한 사람"이다. 팔다리는 짧고 도톰하며 외곽선이 없다.

2D 전신 240px 기준: 몸 (49,43) 142×137 r35, 캡슐 (59,82) 122×63 r31.5, 눈 중심 x98/139 y103, 입 중심 (120,125), 볼 x80/157 y120. 아바타는 얼굴을 키워 32px에서도 입이 보이게 한다. 도면은 [character/2d/construction.svg](character/2d/construction.svg).

### 두 계열

| 계열 | 쓰는 곳 | 파일 |
|---|---|---|
| 3D 클레이 | 64px 이상. 랜딩, 빈 화면과 오류 장면, OG, 앱 아이콘, 말풍선 옆 큰 얼굴, 확정 화면 | `character/3d/`, `scenes/3d/`, `props/3d/` |
| 2D 평면 | 48px 이하. 아바타, 칩, 파비콘, 인라인 배지 | `character/2d/avatar/`, `logo/symbol.svg` |

3D는 무광 클레이 재질에 따뜻한 키 라이트와 접지 그림자가 있다. 렌더는 투명 PNG이며 그림자가 포함돼 있으니 바탕은 밝은 단색(#FAF9F6, #FFF1EC, #FFFFFF)을 권장한다. 2D는 홍시, 크림, 잉크, 볼색만 쓰고 그라디언트를 넣지 않는다. 두 계열의 비례는 같으므로 한 화면에 섞여도 같은 캐릭터로 읽힌다. 단, 한 화면에서 말하는 얼굴은 하나만 둔다.

### 표정 8종

| 이름 | 눈 / 입 / 자세 | 화면 |
|---|---|---|
| `default` | 둥근 눈, 미소, 정면 | 일반 안내, 기본 아바타 |
| `thinking` | 위를 보는 눈, 작은 원형 입, 손을 턱에 | 조건 해석, 이동시간 비교 중 |
| `waiting` | 가늘게 쉰 눈, 작은 미소, 두 손 모음 | 응답 대기, 진행 현황 |
| `happy` | 초승달 눈, 벌린 웃음, 두 팔 올림 | 좋은 소식, 전원 가능 |
| `sorry` | 처진 눈썹, 찡그린 입, 두 손을 얼굴 앞에 | 외부 API 실패, 재시도 안내 |
| `guide` | 윙크, 한쪽 미소, 한 팔 들어 가리킴 | 첫 방문, 입력 방법 설명 |
| `celebrate` | 기쁨 눈, 큰 웃음, 두 팔 번쩍, 살짝 점프 | 확정 직후, 요약 카드 |
| `sleepy` | 감은 눈, 하품, 기울어진 몸 | 아직 아무도 응답하지 않음 |

표정은 진행 상태를 대신 설명하지 않는다. 항상 짧은 문장을 붙인다. 실패 화면에서 반복 동작을 쓰지 않는다.

### 소품과 장면

소품 6종(역명판, 지도 핀, 시계 타일, 달력 타일, 말풍선, 세 명이 모이는 장면)은 캐릭터와 같은 재질과 조명으로 렌더했다. 장면 3종은 `landing-hero`(마주가 세 노선의 합류를 안내), `empty-state`(졸린 마주와 빈 달력), `error-state`(미안한 마주와 금 간 핀). 새 장면이 필요하면 `tools/mazu.js`의 `createProp`과 `render()`에 추가하고 같은 카메라와 조명을 쓴다.

### 역할

| 역할 | 라이트 | 다크 | 규칙 |
|---|---|---|---|
| 화면 바탕 | 중성 50 #FAF9F6 | 중성 900 #24221F | 따뜻한 중성. 녹색 기운 없음 |
| 종이(카드, 시트) | #FFFFFF | #312E2A | |
| 본문 / 보조 | 잉크 / 중성 600 #625D54 | #FAF9F6 / 중성 300 #CCC6BC | |
| 행동 / 위의 글자 | 숲 500 / 흰색 | 숲 300 #7DD4B5 / 잉크 | 버튼, 텍스트 링크, 포커스 링 |
| 선택 면 | 숲 50 #EAF6F0 | 숲 800 #103A32 | 선택한 칩, 셀, 카드 |
| 비서 면 / 배지 / 위의 글자 | 신호 50 / 신호 500 / 신호 900 #44371A | 신호 900 / 신호 500 / 신호 900 | 마주가 말하거나 제안할 때만 |
| 캐릭터 바탕 | 홍시 50 #FFF1EC | 종이 | 캐릭터 뒤 면에만. 버튼에 홍시 금지 |
| 오류 | 홍시 700 #AD3422 | 홍시 200 #FFBBA8 | 글자와 테두리. 캐릭터 색과 혼동되지 않게 글자로만 |
| 구분선 / 입력 경계 | 중성 200 / 중성 500 | 중성 700 / 중성 400 | 장식선을 입력 경계로 쓰지 않음 |

세 원색의 역할은 v2와 같다. 홍시는 캐릭터와 브랜드 인지, 숲은 사용자의 행동, 신호는 마주의 발화. 홍시 위 흰 글자(3.27:1)는 쓰지 않는다. 주요 글자·배경 조합의 대비는 `qa/contrast.json`에 있으며 본문과 버튼은 모두 4.5:1 이상이다.

## 4. 타이포그래피, 간격, 반경, 그림자, 모션

UI 글꼴은 Pretendard, 대체는 Apple SD Gothic Neo.

| 단계 | 크기 / 굵기 / 행간 | 쓰는 곳 |
|---|---|---|
| display | 40 / 700 / 1.2 | 랜딩 헤드라인 |
| h1 | 32 / 700 / 1.25 | 화면 제목 |
| h2 | 24 / 700 / 1.35 | 카드의 핵심 값(날짜, 역 이름) |
| h3 | 20 / 600 / 1.4 | 섹션 제목 |
| body | 16 / 400 / 1.5 | 본문, 마주의 말 |
| label | 14 / 600 / 1.4 | 버튼 보조, 칩 |
| caption | 12 / 400 / 1.5 | 상태, 도움말. 핵심 행동에는 쓰지 않음 |

- 간격: 4pt 단위 `--space-4` ~ `--space-96`. 화면 좌우 24, 카드 안 20, 조밀한 줄 16.
- 반경: xs 4, sm 8, md 12, lg 16, xl 24, 2xl 32, pill. 버튼 16, 입력 12~16, 카드 20~24, 배지는 pill.
- 그림자: sm / md / lg 3단계. 카드에 상시 그림자를 겹쳐 쌓지 않는다. 다크는 그림자 대신 종이 색 차이로 위계를 만든다.
- 모션: fast 120ms(상태 변화), base 200ms(열림·닫힘), slow 320ms(시트), expressive 480ms(마주 등장). 이징은 standard, enter, exit, spring. `prefers-reduced-motion: reduce`에서는 위치 이동을 없애고 불투명도만 남긴다.
- 포커스: `:focus-visible`에 외곽 4px 간격의 2px 숲색 링. 부모의 `overflow: hidden`에 잘리지 않게 한다.

## 5. 로고

심벌, 한글·영문 워드마크, 가로·세로 조합, 단색 흑백. 워드마크 경로는 v2와 같고, 심벌의 얼굴만 v3 캐릭터 얼굴(크림 캡슐, 둥근 눈, 입, 볼)로 바꿨다. 외곽 실루엣과 우하단 절단은 그대로다. 구성 도면은 [logo/construction.svg](logo/construction.svg).

- 보호 여백: 심벌 160px 원본에서 캡슐 높이의 절반(24px) 이상을 사방에 비운다.
- 최소 크기: 가로 조합 너비 120px, 세로 조합 88px, 독립 심벌 24px, 파비콘은 제공한 16·32px PNG만 사용.
- 밝은 바탕에는 원색 조합, 어두운 바탕에는 단색 흰색. 단색 파일의 캡슐은 실제로 뚫려 있어 바탕이 비친다.
- 금지: 늘이기, 기울이기, 심벌 안에 숫자나 이니셜 넣기, 글자 하나만 다른 색으로 강조, 사진 위에 직접 놓기.

## 6. 앱 아이콘, 파비콘, 링크 미리보기

- 앱 아이콘은 3D 마주 기본 표정을 홍시 50 바탕에 올린 렌더(`app-icon/icon-1024.png` 등). 마스커블은 안전 영역 80% 안에 캐릭터를 둔다.
- 파비콘 16·32px은 2D 심벌에서 만든다. 16px에서는 표정보다 브랜드 식별이 우선이다.
- OG 이미지(`og/og-template.svg`, 1200×630)는 왼쪽에 "{호스트}님의 모임"과 날짜, 오른쪽에 3D 랜딩 장면. 호스트 이름과 날짜만 바꿔 쓴다.

## 7. 제품에 적용할 때

- 마주의 말풍선은 종이 면에 신호 노랑 테두리, 왼쪽 아래 짧은 꼬리, "마주의 한마디" 배지로 식별한다. 색을 못 봐도 발화 주체가 드러나야 한다.
- 제안 카드는 "마주가 제안해요" 배지를 달고, 확정 전까지는 선택 면(숲 50)만 쓴다. 확정 버튼은 숲 500 하나.
- 빈 화면은 `scenes/3d/empty-state.png`와 "모임 만들기", 오류는 `error-state.png`와 실패 범위 문장, "다시 시도". 로딩은 2D `thinking` 아바타의 루프(`character/2d/motion/thinking-loop.svg`)와 지금 하는 일을 말하는 문장.
- Tailwind 4에서는 `tokens.json`의 값을 `@theme`에 옮기고, 컴포넌트는 `--color-*` 의미 토큰만 참조한다. `--brand-*`와 램프 원색을 컴포넌트에서 직접 쓰지 않는다.
