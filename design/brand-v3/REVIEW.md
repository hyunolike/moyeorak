# Brand v3 검토 기록

2026년 10월 30일. B2C 시니어 디자이너 관점에서 brand v2를 검토하고, 지적한 일곱 가지를 v3에서 고쳤다. 캐릭터와 소품의 3D 제작, 2D 캐릭터, 토큰, 컴포넌트 시트, 로고 수정, 화면 시안은 Codex가 만들었다. 3D 렌더 실행과 색·구도 보정, 파생 에셋 포장, 이 문서는 Claude가 맡았다.

바뀌지 않은 것: 콘셉트 **합류점**, 캐릭터 이름 **마주**, 네 가지 원색(홍시 #F45B3F, 숲 #176B5B, 신호 #F3CF58, 잉크 #202923), 한글·영문 워드마크의 윤곽.

## 지적 사항과 조치

### 1. 얼굴이 콘센트나 로봇처럼 읽힘

**v2:** 좁은 크림 캡슐 안에 세로 막대 눈 두 개. 입이 작고 볼이 없어 전원 콘센트 인상이 강했다.

**v3:** 캡슐을 넓고 낮게(2D 전신 기준 122×63px) 바꾸고, 그 안에 하이라이트가 있는 둥근 눈, 모든 표정에 보이는 입, 연한 볼을 넣었다. 얼굴 요소는 전부 캡슐 안에 둔다. 심벌도 같은 얼굴로 광학 수정했고, 외곽 실루엣과 우하단 절단은 v2 그대로 유지했다(`tools/logo-notes.md`).

**남은 일:** "처음 보는 사람이 캐릭터라고 말하는지"는 실제 사람에게 보여 줘야 확인된다. 아직 안 했다.

### 2. 표정 간 차이가 작음

**v2:** 기다림과 미안함이 거의 같았고, 생각 중은 점 하나만 더한 수준이었다.

**v3:** 8종으로 늘리고 표정마다 눈 모양, 입 모양, 몸짓을 모두 다르게 했다. 추가한 두 가지는 확정 직후의 `celebrate`(두 팔을 든 자세, 장식 없음)와 아무도 응답하지 않았을 때의 `sleepy`(감은 눈, 하품). 32px 아바타 8종을 `character/2d/expression-sheet.png`에서 한 줄로 비교할 수 있다.

### 3. 평면 스티커라 큰 자리에서 힘이 없음

**v2:** 외곽선 있는 평면 벡터뿐이라 랜딩, 빈 화면, OG 이미지에 넣으면 아이콘처럼 보였다.

**v3:** three.js로 마주를 절차적으로 만들고 Playwright 헤드리스 Chromium(SwiftShader)으로 렌더했다. 둥근 상자 몸, 거칠기 0.93의 무광 클레이 재질, 따뜻한 키 라이트 하나와 부드러운 필, 접지 그림자. 외곽선은 없다. 가는 막대 팔과 노란 종점은 짧고 도톰한 팔다리로 바꿨다. 표정은 별도 모델이 아니라 `tools/mazu.js`의 파라미터다. 정면·측면, 30° 간격 턴테이블 12장, `mazu.glb`까지 같은 코드에서 나온다.

**보정:** 첫 렌더에서 홍시색이 톤매핑 때문에 살구색으로 바랬다. 노출 1.2→0.98, 반구광 2.25→1.7로 낮춰 그늘진 면이 원색에 가깝게 맞췄다. 빛을 받는 면이 밝아지는 것은 재질의 성격이라 그대로 두었다.

### 4. 2D와 3D의 역할 분리

**v3:** 64px 이상은 3D 렌더, 48px 이하는 2D 평면 얼굴을 쓴다. 2D 아바타는 v2 얼굴이 아니라 3D의 비례(넓은 캡슐, 둥근 눈, 입)에서 다시 그렸다. 두 계열이 같은 캐릭터로 읽히는지는 `brand-board.png`의 3D 줄과 2D 줄을 나란히 놓고 확인했다.

### 5. 디자인 시스템이 색 목록뿐이었음

**v3:** `tokens.css`와 W3C 형식 `tokens.json`에 다음을 추가했다.
- 홍시, 숲, 신호, 따뜻한 중성색의 50~900 램프
- 4pt 간격(4~96), 반경 6단계와 캡슐, 그림자 3단계(라이트·다크), 모션 시간 5단계와 이징 4종, 글자 7단계
- 라이트·다크 역할 토큰(`--brand-*`)과 화면용 의미 토큰(`--color-*`)

컴포넌트는 `components/components.md`에 9종(버튼 3종, 조건 칩, 참여자 상태, 모임 카드, 마주 말풍선, 제안 카드, 시간표 셀, 입력, 하단 고정 CTA)의 상태와 접근성 계약을 적었고, `components/components.svg`에 49개 상태를 라이트와 다크로 그렸다.

### 6. 노란 판 말풍선이 무겁고 다크가 핀테크 같음

**v2:** 말풍선 전체가 신호 노랑 면. 다크 배경이 검은 녹색(#17251F)이라 금융 앱 인상.

**v3:** 말풍선은 흰 종이 면에 노랑 테두리, 짧은 꼬리, "마주의 한마디" 노랑 배지로 바꿨다. 노랑 위 글자는 잉크가 아닌 신호 900(#44371A)으로 내려 9.9:1에서 더 차분한 대비를 얻었다. 숲색은 버튼과 선택 상태에만 쓰고, 선택 면은 숲 50(#EAF6F0)이다. 다크 바탕은 따뜻한 중성 900(#24221F), 카드는 #312E2A로 바꿔 녹색 기운을 뺐다. 대비 수치는 `qa/contrast.json`.

### 7. 화면 시안이 평범함

**v3:** 실제 흐름 다섯 장면(랜딩, 모임 홈, 가능 시간 말로 입력, 제안 카드, 확정 요약)과 모임 홈 다크를 새로 그렸다. 랜딩은 3D 장면 `landing-hero`, 확정 화면은 3D `celebrate`를 쓴다. 모든 화면에 주요 행동은 하나만 둔다.

## 일부러 바꾸지 않은 것

- 워드마크 "모여락"과 "moyeorak"의 경로. 글자 설계는 v2에서 끝났고 고칠 이유가 없었다.
- 심벌의 외곽 실루엣과 우하단 절단. 얼굴만 고쳐야 기존 심벌 인상이 이어진다.
- 캐릭터 안의 그라디언트 금지 규칙. 3D는 조명으로 입체를 얻지만, 2D 평면 계열에는 여전히 단색만 쓴다.

## 제작 과정 메모

- Codex 작업이 모델 용량 오류로 세 번 끊겼고, Codex 샌드박스에서는 Chromium 실행이 막혀 3D 렌더를 못 했다. 모델과 리그(`tools/mazu.js`), 렌더 스크립트(`tools/render.mjs`)는 Codex가 썼고 실행과 보정은 바깥 셸에서 했다.
- Codex가 Chromium 대안으로 시작한 오프라인 렌더 파일들(`render-offline.html`, `clay-render.cpp`)은 쓰지 않아 지웠다.
- 재렌더: `cd design/brand-v3/tools && node render.mjs` (의존성은 `npm install` 뒤, Playwright 브라우저는 `~/Library/Caches/ms-playwright`에 있는 것을 쓴다).
