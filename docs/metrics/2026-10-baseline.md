# 2026-10 기준선 지표

리뉴얼 전 서비스의 여섯 지표를 기존 스키마 기준으로 고정한 결과다. 정의는 `docs/metrics/baseline-queries.sql`에 있고, 새 앱의 집계 함수도 같은 정의를 따른다.

## 운영 DB 값

운영 DB 접근 정보가 이 작업 환경에 없어서 값은 비워 두었다. 호스트가 아래 명령으로 실행해 채운다.

```bash
psql "$DATABASE_URL" -f docs/metrics/baseline-queries.sql
```

실행 일시: 호스트 실행 필요

| 지표 | 값 |
|---|---|
| 모임 수 | 호스트 실행 필요 |
| 확정률 | 호스트 실행 필요 |
| 참여 완료율 | 호스트 실행 필요 |
| 생성에서 확정까지 중앙값(시간) | 호스트 실행 필요 |
| 재사용률(30일) | 호스트 실행 필요 |
| 공유 수 | N/A (새 앱에서부터 측정) |
| 제안 수락률 | N/A (새 앱에서부터 측정) |

## 로컬 검증

2026-10-30에 로컬 개발 DB(`moyeolak-postgres` 컨테이너)에서 SQL 파일을 위에서 아래까지 실행했고 오류 없이 지표마다 한 행씩 나왔다. 로컬 DB에는 임시 테스트 데이터만 있어서 이 값은 기준선으로 쓰지 않는다.

```bash
docker exec -i moyeolak-postgres psql -U moyeolak -d moyeolak -f - < docs/metrics/baseline-queries.sql
```

## 정의에서 정한 것

- 생성에서 확정까지는 확정 시각 컬럼이 따로 없어서, 확정된 일정 투표의 `updated_at`을 확정 시각으로 근사한다. 확정 후에 다시 갱신되면 값이 커질 수 있다.
- 참여 완료율은 `participant_count`가 비어 있거나 0인 모임을 제외하고, 모임별 비율이 1을 넘으면 1로 자른다.
- 재사용률은 호스트의 `local_storage_key`가 같은 브라우저를 뜻한다고 보고, 첫 모임 생성 후 30일 안에 두 번째 모임을 만든 키의 비율로 계산한다. 브라우저 저장소를 지운 사용자는 새 사용자로 잡힌다.
