# 시간 파싱 평가 세트

단톡방에서 쓰는 말투의 일정 문장을 투표 가능한 시간 칸으로 바꾸는 파서를 평가하기 위한 케이스 모음이다. 1단계 계획이 `time-parse-cases.jsonl`을 읽어 평가를 돌린다.

## 현재 상태

시작 예시 10개만 들어 있다. 나머지 40개는 호스트가 실제 단톡방 문장으로 채워서 총 50개를 맞춘다. 직접 만든 문장이 아니라 실제로 오간 문장을 써야 평가가 의미가 있다.

## 한 줄의 형식

```json
{"today": "2026-11-02", "poll": {"dateOptions": ["2026-11-02", "..."], "startMinute": 540, "endMinute": 1440}, "text": "금요일 오후 괜찮아", "expected": ["2026-11-06T12:00", "..."]}
```

- `today`는 문장을 쓴 날이다. 상대 표현의 기준이 된다.
- `poll.dateOptions`는 투표 후보 날짜이고, 예시에서는 `today`부터 14일 연속이다. `startMinute`와 `endMinute`는 하루 중 투표 가능한 범위를 분 단위로 나타낸다(540은 09:00, 1440은 24:00).
- `expected`는 가능하다고 말한 30분 칸의 시작 시각 목록이다. `YYYY-MM-DDTHH:mm` 형식의 로컬 시각이고 시간순으로 적는다.

## 시간대 표현 기준

| 표현 | 범위 |
|---|---|
| 오전 | 09:00부터 12:00 전까지 |
| 점심 | 11:30부터 14:00 전까지 |
| 오후 | 12:00부터 18:00 전까지 |
| 저녁 | 18:00부터 21:00 전까지 |
| 밤 | 21:00부터 24:00 전까지 |
| N시 이후 | N시부터 `endMinute`까지 |

주 단위 표현은 월요일에 시작해 일요일에 끝나는 달력 주를 기준으로 한다. 담주와 다음 주는 `today`가 속한 주의 다음 주이고, 이번 주말은 `today`가 속한 주의 토요일과 일요일이다. 요일만 말하면(예: 금요일) 후보 날짜 안에서 그 요일에 해당하는 날을 모두 포함한다.

호스트가 새 케이스를 쓸 때 위 기준과 다른 해석이 자연스럽다면 기준을 바꾸지 말고 먼저 이 표에 논의를 남긴다. 기준이 흔들리면 기존 케이스의 정답이 함께 흔들린다.

## 검증

각 줄이 JSON으로 읽히고 `dateOptions`가 14개인지 확인한다.

```bash
python3 -I -c "import json; [json.loads(l) for l in open('docs/eval/time-parse-cases.jsonl')]"
```

## 실행

`app/`에서 모델 이름을 쉼표로 이어 넘기면 한 번에 여러 모델을 비교한다. 실제 모델은 `NVIDIA_API_KEY`가 필요하고, 모델 이름이 그대로 NVIDIA 모델 ID로 쓰인다. `mock`은 `mockParse`를 쓴다.

```bash
cd app
pnpm eval:time-parse --models mock
NVIDIA_API_KEY=... pnpm eval:time-parse --models meta/llama-3.3-70b-instruct,other/model [--cases ../docs/eval/time-parse-cases.jsonl]
```

모델별 정확도(30분 칸이 정답과 완전히 같은 케이스의 비율), 평균 지연, 스키마 위반 수를 표로 찍는다. 정확도가 95% 미만인 모델이 하나라도 있으면 종료 코드 1이다. 케이스의 기준 시각은 그 줄의 `today` 서울 정오다.

케이스별 결과(빠진 칸, 더한 칸, 지연)는 `docs/eval/results/{날짜}-{모델 이름의 /를 _로}.json`에 쓴다. 이 파일은 커밋하지 않는다.

## 모델 선택 기록

교체 배포 전에 위 명령으로 후보 모델을 평가하고 결과를 여기에 적는다. 정확도 95% 이상인 모델을 `NVIDIA_MODEL_PARSE`로 쓴다. 구조화 출력 방식은 `app/src/server/ai/provider.ts`의 `DEFAULT_STRUCTURED_OUTPUT`이고, 평가에서 더 나은 쪽으로 바꾼다.

95%에 닿는 모델이 없으면 가장 높은 모델을 쓰되 그 정확도를 함께 적는다. 이 경우에도 말로 남기기는 시간표를 칠해 보여 주기만 하고, 사용자가 **이 시간으로 저장**을 눌러야 저장된다.

|---|---|---|---|---|---|
