# 프로젝트 2: 공유, 다시 제안, 다시 모이기, 응답 마감, 빠진 이벤트

작성일 2026-11-08. 사용자가 질문을 건너뛰고 바로 진행해 달라고 해서, 아래 판단은 모두 작성자(Claude)의 판단이다. 판단이 들어간 곳은 **[판단]**으로 표시했다.

## 왜

기획 검토(2026-11-03)에서 남은 문제는 세 가지다.

1. 단톡방에 보내는 링크가 글자뿐이라 눈에 덜 띄고, 확정한 약속을 일정에 남길 방법이 없다. "역에서 어디 갈지"도 다시 단톡방에서 정해야 한다.
2. 제안 두 개가 마음에 안 들면 다시 단톡방으로 돌아간다. 응답을 언제까지 해야 하는지 기준이 없어 재촉에도 근거가 없다.
3. 모임을 마친 같은 단톡방이 다음 약속을 잡을 때 처음부터 다시 만들어야 한다. 그리고 어디서 막히는지 알려 줄 이벤트가 비어 있다.

성공 기준은 리뉴얼 설계서와 같다. 확정률과 30일 재사용률이 오르는지, 그리고 이번에 넣는 이벤트로 그 변화를 볼 수 있는지다.

## 범위

| # | 기능 | 한 줄 |
|---|---|---|
| A | 카카오톡 공유 카드 | 초대 링크와 약속 카드를 썸네일과 버튼이 있는 카카오톡 카드로 보낸다 |
| B | 캘린더 추가 | 확정 약속을 .ics 파일이나 구글 캘린더에 넣는다 (#26 복원) |
| C | 역 근처 장소 | 확정 역 주변의 목적에 맞는 가게 몇 곳을 약속 카드 아래에 보여 준다 (#26 복원, 목적 반영) |
| D | 조건 바꿔 다시 제안 | 제안이 마음에 안 들면 요일, 시간대, 길이, 다른 역 같은 조건을 골라 다시 받는다 |
| E | 응답 마감 | 모임을 만들 때나 나중에 응답 마감 시각을 정한다. 마감은 안내와 재촉의 근거이고, 응답을 막지는 않는다 |
| F | 같은 멤버로 또 모이기 | 지난 모임에서 새 모임을 만들면 설정을 이어받고, 지난 멤버는 이름을 한 번에 골라 들어온다 |
| G | 빠진 이벤트와 지표 | 재촉, 말로 입력한 시간을 고쳤는지, 제안 넘김과 다시 제안, 확정 되돌리기 등을 기록하고 관리자 지표에 보인다 |

### 하지 않는 것

- #26의 "현재 위치로 출발지 찾기"는 이번에 넣지 않는다. 프로젝트 2 목록에 없고, 위치 권한 흐름은 실기기 확인이 따로 필요하다. **[판단]**
- 마감이 지나도 응답을 막거나 자동으로 확정하지 않는다. 푸시 알림, 예약 작업(cron)도 없다. 친구 약속에서 늦게 응답한 사람을 막으면 오히려 단톡방으로 돌아가기 때문이다. **[판단]**
- 모임을 넘나드는 친구 목록, 계정, 로그인은 만들지 않는다. "같은 멤버"는 지난 모임의 참여자 이름과 기기 키로만 알아본다.
- 장소 예약이나 제휴 연결은 하지 않는다. 근처 장소는 카카오맵 장소 페이지로만 연다.

### 망하는 경우 (anti-goals)

- 카카오 SDK가 안 뜨는 환경(키 없음, 도메인 미등록, 인앱 브라우저 차단)에서 공유 버튼이 아무 일도 안 하는 것. 반드시 지금의 링크 복사로 떨어져야 한다.
- 다시 제안이 같은 카드를 또 내놓는 것. 조건을 골랐는데 맞는 시간이 없으면 "조건에 맞는 시간이 없어요"라고 솔직하게 말해야 한다.
- 마감 문구가 압박처럼 읽히는 것. 재촉 메시지 규칙(탓하지 않기)을 그대로 지킨다.
- 같은 멤버로 또 모이기가 지난 모임의 응답(투표, 출발지)까지 복사하는 것. 이름과 설정만 이어받는다.

## 제약

- 기존 스택을 그대로 쓴다: Next.js 16, Drizzle, Neon Postgres, TanStack Query, Biome, Vitest, Playwright.
- 외부 호출은 모두 `MOCK_EXTERNAL=1`에서 모의 응답을 낸다. e2e는 이 모드로 돈다.
- 스키마 변경은 drizzle 마이그레이션으로만 한다. 운영 반영 순서는 마이그레이션 → 배포다.
- 사용자에게 보이는 문구는 해요체, 자연스러운 한국어. 가운뎃점 나열을 쓰지 않는다.
- 이벤트 테이블(`meeting_events`)은 `type`만 있다. 새 이벤트도 `type` 문자열만 늘리고, 테이블에 payload 컬럼은 넣지 않는다. **[판단]** 세부 값이 꼭 필요한 이벤트는 이름에 담는다(예: `vote_from_text`, `vote_from_text_edited`).

## 기능별 설계

### A. 카카오톡 공유 카드

- 카카오 JavaScript SDK(`https://t1.kakaocdn.net/kakao_js_sdk/<고정 버전>/kakao.min.js`)를 필요할 때 한 번만 불러온다. 지도 SDK 로더(`src/lib/kakao-sdk.ts`)와 같은 방식으로 캐시한 Promise를 쓴다.
- 키는 `NEXT_PUBLIC_KAKAO_JS_KEY`를 쓰고, 없으면 `NEXT_PUBLIC_KAKAO_MAP_KEY`를 쓴다. 지도 키도 같은 앱의 JavaScript 키이고, 도메인도 이미 등록되어 있기 때문이다. **[판단]**
- 피드 템플릿(`Kakao.Share.sendDefault`, `objectType: "feed"`)으로 보낸다.
  - 초대: 제목 "{호스트}님의 모임", 설명은 지금 OG 설명(`meeting-preview.ts`)과 같은 문장, 이미지는 모임 OG 이미지 절대 주소, 버튼 하나 "참여하기" → `/meetings/{id}`.
  - 약속 카드: 제목 "{호스트}님의 모임이 정해졌어요", 설명은 날짜와 시간, 역 이름, 버튼 "약속 보기" → `/meetings/{id}/summary`.
- 버튼 위치:
  - `ShareButton`: 기본 동작을 "카카오톡으로 보내기"로 바꾸고, 옆에 작은 "링크 복사"를 남긴다. SDK를 못 쓰면 지금처럼 복사만 한다.
  - 약속 카드의 "단톡방에 공유하기": 카카오 카드로 보내고, 실패하면 지금의 `navigator.share` 또는 복사로 떨어진다.
  - 재촉 시트는 문장 자체가 중요해서 지금 동작(복사, `navigator.share`)을 유지한다. **[판단]**
- 데스크톱에서도 SDK가 카카오톡 PC 또는 웹 공유 창을 연다. SDK 로딩이 3초 안에 안 끝나면 복사로 떨어진다.
- 이벤트: 성공 여부와 관계없이 보내기 버튼을 누르면 `shared`(지금과 같음), 카카오 카드로 보낸 경우 `kakao_shared`를 함께 기록한다.

### B. 캘린더 추가 (#26 복원)

- #26의 `src/lib/calendar.ts`, `GET /api/meetings/[id]/calendar`(.ics), `CalendarAction`을 가져온다.
- 바꿀 점: 일정 끝은 `summary.end`가 있으면 그것을 쓰고, 없을 때만 시작부터 2시간으로 둔다.
- 약속 카드 액션 줄의 "글로 복사"와 "카카오맵" 사이에 "캘린더" 타일을 둔다. 시작 시각이 없는 장소만 모임은 타일을 숨기고 .ics API는 404를 준다(#26과 같음).
- 이벤트: `.ics` 받기나 구글 캘린더 링크를 누르면 `calendar_added`.

### C. 역 근처 장소 (#26 복원, 목적 반영)

- #26의 `searchNearbyPlaces`, `nearby-service`, `GET /api/meetings/[id]/nearby`, `NearbyPlaces`를 가져온다.
- 바꿀 점: 찾는 종류를 모임 목적(`meetings.purposes`)에 맞춘다. 목적이 없으면 #26처럼 식당과 카페.
  - 밥 FD6, 카페 CE7, 구경 CT1과 AT4는 카테고리 검색. 술은 키워드 "술집", 공부는 키워드 "스터디카페"(가게 수 집계 `countVenues`와 같은 기준).
  - 목적마다 3곳, 최대 두 목적까지 보여 준다(목적 순서는 `PURPOSES` 표 순서). **[판단]**
- 확정 역 좌표 기준 반경 500m, 정확도순. external_cache에 좌표와 종류를 키로 7일 캐시, 실패는 캐시하지 않는다.
- 약속 카드 아래 "근처에서 만나기 좋은 곳" 섹션. 불러오는 중이거나 실패하거나 비면 섹션을 숨긴다.
- `kakao-local.ts`의 카테고리 URL 만들기는 `countVenues`와 함께 쓰도록 정리한다.

### D. 조건 바꿔 다시 제안

- 제안 화면의 카드 묶음 아래와 "준비한 제안은 여기까지예요" 화면에 "조건 바꿔 다시 받기" 버튼을 둔다. 누르면 시트가 열린다.
- 시간 제안 조건(여러 개 고를 수 있음, 비우면 조건 없음):
  - 요일: 평일, 주말
  - 시간대: 낮(17시 전 시작), 저녁(17시부터 시작)
  - 길이: 2시간 이상
- 장소 제안 조건:
  - "지금 제안한 역 말고": 지금 열려 있는 제안의 역들을 빼고 다시 고른다.
  - 목적 바꾸기: 지금 있는 목적 칩(`PurposeChips`)을 시트 안에 둔다. 바꾸면 기존 목적 변경 API를 쓴다.
- API: `POST /api/meetings/[id]/suggestions`에 선택 본문 `{ conditions?: { days?: "weekday"|"weekend", time?: "day"|"evening", minHours?: 2, excludeStationIds?: number[] } }`. 본문이 없으면 지금과 같다.
- 규칙: `pickSchedule`과 `pickLocation`에 조건 필터를 넣는다. 조건은 후보를 거르기만 하고 순위 규칙은 그대로다.
- 조건에 맞는 후보가 없으면 409 `NO_MATCH`를 주고, 화면은 "고른 조건에 맞는 시간이 없어요. 조건을 줄여 볼까요?"를 보여 준다. 기존 제안은 지우지 않는다.
- 조건은 제안 payload에 `conditions`로 남기고, 카드 위에 "주말 저녁으로 다시 고른 제안" 같은 한 줄을 보여 준다. 이유 문장(AI)에도 조건을 넘겨 "주말 저녁 중에서는" 같은 표현이 맞게 나오게 한다. 숫자 검사(number-guard)와 "모두 가능" 검사는 그대로 둔다.
- 이벤트: 카드 "다른 제안 보기"는 `suggestion_skipped`, 조건을 넣어 다시 받으면 `resuggested`.

### E. 응답 마감

- `meetings.respond_by timestamptz null`을 추가한다.
- 만들 때: 모임 만들기 폼에 "응답 마감" 선택을 둔다. 보기는 "정하지 않음"(기본), "내일 밤 10시", "모레 밤 10시", "3일 뒤 밤 10시". 시간 투표 기간 마지막 날보다 늦은 보기는 숨긴다. **[판단]** 밤 10시는 단톡방이 가장 활발한 시간대에 맞춘 값이다.
- 나중에: 모임 홈에서 호스트가 "응답 마감 정하기/바꾸기"로 같은 보기를 고르거나 지운다. `PATCH /api/meetings/[id]/deadline { respondBy: string|null }`, 호스트만.
- 단계가 넘어가면(시간 확정 후 장소 모으기로 넘어가면) 마감을 지운다. 새 단계의 마감은 호스트가 다시 정한다. 확정되면 마감은 화면에 더 이상 보이지 않는다.
- 보여 주기:
  - 모임 홈 진행 카드에 "11월 10일(화) 밤 10시까지 응답해 주세요". 마감 24시간 전부터는 "오늘 밤 10시까지예요"처럼 가깝게 말한다.
  - OG 설명과 카카오 초대 카드 설명 끝에 "11월 10일(화) 밤 10시까지" 한 마디를 붙인다.
  - 재촉 메시지: 문장 틀과 AI 입력에 실제 마감을 넘긴다. 프롬프트의 "마감 시한을 지어내지 않는다"는 "주어진 마감만 쓰고, 없으면 지어내지 않는다"로 바꾼다.
- 마감이 지나면: 응답은 그대로 받는다. 호스트 홈의 주 버튼이 "마감이 지났어요. 지금 응답으로 제안 받기"로 바뀐다(응답 2명 이상일 때). 참여자 홈에는 "마감이 지났지만 아직 응답할 수 있어요"를 보여 준다.
- 이벤트: 마감을 정하거나 바꾸면 `deadline_set`.

### F. 같은 멤버로 또 모이기

- `meetings.source_meeting_id varchar(21) null`(지난 모임 id, FK 없음, 지난 모임이 지워져도 남는다)을 추가한다.
- 버튼 위치: 약속 카드의 하단 CTA 아래 보조 버튼 "같은 멤버로 또 모이기", 그리고 "내 모임"의 지난 모임 줄. 그 모임의 참여자라면 누구나 누를 수 있다. 누른 사람이 새 모임의 호스트가 된다.
- 누르면 `/new/<scope>?from=<지난 모임 id>`로 간다. 폼이 지난 모임에서 범위, 목적, 예상 인원(지난 모임의 표시 인원)을 채우고, 호스트 이름은 누른 사람의 지난 모임 이름으로 채운다. 시간 투표 기간은 새로 고른다(지난 날짜는 의미 없음).
- 서버: `POST /api/meetings`에 선택 `sourceMeetingId`. 만드는 사람이 그 모임의 참여자(기기 키 기준)일 때만 받아들이고, 아니면 무시한다. **[판단]** 남의 모임 id로 이름 목록을 빼 가지 못하게 하려는 것이다.
- 새 모임 초대 화면: `source_meeting_id`가 있으면 들어오는 사람에게 "지난번 멤버" 이름 칩을 보여 준다(지난 모임 참여자 중 새 모임에 아직 없는 이름, 호스트 제외). 칩을 누르면 이름 칸이 채워지고 바로 참여한다.
  - 지금 기기 키가 지난 모임의 참여자와 같으면 그 이름을 맨 앞에 "지난번엔 준호님으로 참여했어요"로 보여 준다.
  - 이름 목록은 새 모임의 초대 화면 API에서만 내려 주고, 지난 모임의 응답 내용은 내려 주지 않는다.
- 지난 모임과 새 모임을 잇는 표시는 그 밖에는 없다. 응답, 출발지, 제안은 복사하지 않는다.
- 이벤트: 새 모임에 `created`와 함께 `regathered`. 관리자 지표의 재사용률 옆에 "같은 멤버로 다시 모인 모임 수"를 둔다.

### G. 빠진 이벤트와 지표

| `kakao_shared` | 카카오 카드로 보냄 | 클라이언트 |
| `calendar_added` | .ics 받기나 구글 캘린더 링크 | 클라이언트 |
| `vote_from_text` | 말로 입력해 칠한 시간을 그대로 저장 | 서버, 투표 저장 요청의 `source` 값으로 |
| `vote_from_text_edited` | 말로 입력해 칠한 뒤 손으로 고쳐 저장 | 서버 |
| `suggestion_skipped` | 카드에서 "다른 제안 보기" | 서버, reject 라우트 |
| `resuggested` | 조건을 넣어 다시 제안 받음 | 서버 |
| `step_confirmed` | 둘 다 모임에서 시간만 확정해 장소 단계로 넘어감 | 서버 |
| `unconfirmed` | 확정 되돌리기 | 서버 |
| `deadline_set` | 마감을 정하거나 바꿈 | 서버 |
| `regathered` | 같은 멤버로 새 모임을 만듦 | 서버 |

- 투표 저장 `PUT schedule/votes`에 선택 `source: "manual"|"text"|"text_edited"`를 받는다. 클라이언트는 말 입력으로 칠한 뒤 칸을 하나라도 바꿨으면 `text_edited`, 안 바꿨으면 `text`, 말 입력을 안 썼으면 `manual`(기록 없음)을 보낸다. `vote_done`은 지금처럼 늘 남긴다.
- 재촉 시트의 `shared`를 `nudge_sent`로 바꾸면 관리자 지표 "모임당 공유 수"가 조금 줄어든다. 링크 공유와 재촉을 구분하려는 의도된 변화이고, 지표 표에 설명을 붙인다.
- 관리자 지표(`/admin/metrics`)에 줄을 더한다:
  - 재촉 뒤 24시간 안에 응답이 늘어난 비율: `nudge_sent`가 있는 모임 중, 그 뒤 24시간 안에 `vote_done` 또는 `departure_done`이 있는 모임의 비율.
  - 말 입력 그대로 저장 비율: `vote_from_text` / (`vote_from_text` + `vote_from_text_edited`).
  - 제안 넘김 수와 다시 제안 수(모임당 평균).
  - 같은 멤버로 다시 모인 모임 수.
  - 카카오 카드 공유 비율: `kakao_shared` / `shared`.

## 확인 방법

- `pnpm check`, `pnpm test`, `pnpm build`, `pnpm e2e`가 통과한다.
- e2e에 새 흐름을 하나씩 넣는다: 카카오 SDK가 없을 때 복사로 떨어짐, 캘린더 시트와 .ics 응답, 근처 장소 섹션, 조건 바꿔 다시 받기(맞는 시간 있음과 없음), 마감 정하기와 마감 지난 화면, 같은 멤버로 또 모이기에서 이름 칩으로 참여.
- 실제 카카오톡 공유 창은 자동 테스트로 확인할 수 없다. 배포 뒤 사람이 휴대폰에서 한 번 눌러 본다.
