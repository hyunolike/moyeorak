# 모여락 디자인 시스템 v4 설계

## 왜 다시 만드는가

호스트는 지금 화면 전체가 AI가 만든 서비스처럼 보인다고 판단했다. 원인은 brand-v3의 바탕 조합이다.

- 3D 클레이 캐릭터 마주가 화면마다 크게 나와 말을 건다.
- 둥근 모서리와 파스텔 톤이 모든 요소에 똑같이 깔려 있다.
- 거의 모든 내용을 카드와 말풍선으로 감싼다.

3단계 기능(조건을 말로 바꿔 다시 제안, 지난 출발지 재사용, 당일 안내)을 만들기 전에 시스템을 새로 세운다. 기준은 "대기업 IT 서비스에서 10년 넘게 일한 디자이너가 만든 것처럼 보이는가"이다. 호스트가 그런 서비스로 꼽은 곳은 토스, 놀(NOL), 여기어때, 네이버다. 그중 **놀과 여기어때처럼 색과 표정이 살아 있는 쪽**이 모여락의 방향이다.

친구들끼리 약속을 잡는 서비스라서, 업무 도구처럼 차갑지 않고 놀러 가는 기분이 나야 한다. 그렇다고 장식으로 기분을 내지는 않는다. 또렷한 글자 크기 차이, 아껴 쓰는 강한 색, 목록과 여백으로 만든 구조로 낸다.

## 목표

1. 새 브랜드: 로고(심볼과 워드마크를 합친 형태), 색, 글꼴, 아이콘, 작은 마주.
2. 새 토큰과 컴포넌트 라이브러리를 앱에 적용한다.
3. 모든 화면을 새로 배치한다. 화면 흐름과 기능은 지금과 같다.
4. 로고와 그래픽 에셋은 Codex로 만든다.
5. 결과물이 한 화면만 떼어 봐도 AI가 만든 것처럼 보이지 않는다.

## 하지 않는 것

- 기능, API, DB는 바꾸지 않는다. 화면이 부르는 엔드포인트와 응답 형태는 그대로다.
- 3단계 기능은 이번 범위가 아니다.
- 다크 모드 화면은 만들지 않는다. 토큰은 다크 값을 나중에 넣을 수 있는 구조로 짓되, 앱은 지금처럼 밝은 화면으로 고정한다(내 판단).
- 마케팅 랜딩 페이지를 따로 만들지 않는다. 지금의 첫 화면(`/`) 하나를 새로 배치한다.

## 실패로 보는 것 (기술적으로 돌아가도)

- 보라색이나 보라에서 파랑으로 가는 그라데이션, 유리 효과(glassmorphism), 발광 효과.
- 마주가 화면 중앙에 크게 나오거나, 한 화면에 마주 얼굴이 둘 이상 나온다.
- 모든 덩어리에 같은 둥근 모서리와 그림자를 준 카드 더미.
- 섹션 머리에 이모지를 붙인다.
- shadcn/ui 기본 모양(회색 테두리, `rounded-md`, 기본 Lucide 아이콘)이 그대로 드러난다.
- 3D 클레이 렌더를 주된 그래픽으로 쓴다.

## 내가 정한 것

### 라이브러리: shadcn/ui on Base UI

- **선택 이유:** Tailwind 4를 쓰는 지금 앱에 가장 자연스럽게 붙는다. shadcn/ui는 컴포넌트 소스를 저장소에 복사해 넣는 방식이라 겉모양을 모여락 토큰으로 완전히 바꿀 수 있다. 2026년 7월부터 Base UI가 기본 바탕이고, 접근성과 키보드 동작은 Base UI가 맡는다.
- **검토한 대안:** React Aria(접근성 최우선이지만 스타일을 전부 직접 만들어야 함), HeroUI(이미 모양이 입혀져 있어 흔한 인상을 벗기 어려움).
- **조건:** 실패 조건 때문에 기본 스타일은 그대로 쓰지 않는다. 컴포넌트를 받으면 반드시 v4 토큰으로 다시 입힌다.
- **처음 받을 컴포넌트:** Button, Input, Textarea, Dialog, Drawer(아래에서 올라오는 시트), Tabs, Toast, Tooltip, Toggle Group. 나머지는 화면이 필요로 할 때 받는다.
- **아이콘:** 일반 UI 아이콘은 Tabler Icons(선 굵기 조절, 24px 격자, 수가 많음)를 쓴다. 모여락에만 있는 개념(마주, 지하철역, 모이는 지점, 시간 칸)은 Codex로 같은 격자에 맞춰 그린다.

### 글꼴: Pretendard 유지

Pretendard는 이미 `app/public/fonts`에 들어 있고, OG 이미지 렌더에도 쓰인다. 한국 서비스에서 가장 무난하고 굵기가 다양해서 바꾸지 않는다. 대신 쓰는 방식을 바꾼다.

- **큰 제목:** Bold 800, 자간 -3%로 크고 촘촘하게.
- **본문:** 15~16px에 줄간격 1.5.
- **숫자:** 시간, 인원, 분처럼 줄을 맞춰야 하는 숫자는 `tabular-nums`.
- **굵기 추가:** ExtraBold(800)가 없으면 추가한다.

### 색 체계

- **탠저린:** 50~900 단계를 만든다. 500이 `#FF6A13`이다.
- **잉크 중립색:** 순수 회색이 아니라 탠저린 쪽으로 아주 살짝 따뜻하게 기운 회색 계열이다. 글자는 잉크 900(`#17181A` 근처), 바탕은 흰색과 아주 옅은 회색 두 단계다.
- **의미 색:** 성공, 주의, 위험은 브랜드 색과 따로 둔다. 위험을 빨강으로 쓰면 탠저린과 붙어 보이니, 위험은 더 붉고 어둡게, 주의는 노랑 쪽으로 떨어뜨린다.
- **보조 색:** 하나만 둔다. 시간표에서 "가능한 칸"의 농도를 표현할 때와 1순위 표시에만 쓴다. 후보는 탠저린 단계 자체를 쓰는 것이다. 다른 색을 섞으면 화면이 산만해진다.
- **버튼 글자색 (호스트 결정):** 탠저린 500(`#FF6A13`) 바탕 위 글자는 흰색이 아니라 잉크색(`#17181A` 근처)이다. 흰 글자는 대비 2.87:1로 WCAG AA에 못 미치고, 잉크 글자는 6.2:1이다. 주 버튼, 아래 고정 버튼, 1순위 표시, 선택된 시간표 칸, 앱 아이콘의 심볼 모두 같은 규칙을 따른다. 흰 바탕 위에 탠저린 글자를 쓸 때는 대비가 모자라므로(2.87:1), 글자용으로는 700 단계(4.5:1 이상이 나오는 단계)를 쓴다.

### 형태와 깊이

- **모서리:** 세 단계만 쓴다. 작은 요소(칩, 입력칸 안쪽)는 8px, 버튼과 입력칸은 14px, 시트와 큰 패널은 24px. 목록 행은 모서리가 없다.
- **구분:** 카드 테두리 대신 목록과 8px 두께의 회색 구역 띠(토스와 여기어때가 쓰는 방식)로 나눈다.
- **그림자:** 아래에서 올라오는 시트와 떠 있는 버튼에만 쓴다.

### 움직임과 상호작용

호스트가 "인터랙티브한 UI/UX를 넣을 수 있으면 넣어 달라"고 했다. 놀과 여기어때처럼 손에 반응이 느껴지게 만들되, 움직임은 정보를 전달할 때만 쓴다. 장식으로 반짝이거나 떠다니는 것은 실패 조건과 같다.

**기본 규칙**
- **속도:** 누를 때의 반응은 짧게(120~240ms) 한다. 닫힐 때가 열릴 때보다 빠르다.
- **물리감:** 손으로 끄는 동작(시트, 시간표 드래그)은 손을 떼는 순간의 속도를 이어받는 스프링으로 움직인다.
- **접근성:** `prefers-reduced-motion`이면 위치 이동을 빼고 투명도 변화만 남긴다.
- **라이브러리:** Motion(motion.dev, 옛 Framer Motion)을 쓴다(내 판단). 레이아웃 전환, 제스처, 스프링을 한 곳에서 다룬다. CSS 전환으로 충분한 곳(누름, 호버)은 CSS로 둔다.

**화면별 상호작용**

| 자리 | 상호작용 |
|---|---|
| 시간표 투표 | 손가락으로 쓸어내리면 칸이 따라 칠해지고, 칠해지는 칸이 살짝 커졌다가 자리를 잡는다. 지원하는 기기에서는 칸을 칠할 때 짧은 진동(`navigator.vibrate`)을 준다. 아래 고정 버튼에 고른 시간 수가 실시간으로 바뀐다 |
| 말로 입력하기 | 문장을 보내면 해석된 칸이 시간 순서대로 하나씩 칠해진다. 사용자가 무엇이 칠해졌는지 눈으로 따라갈 수 있게 하려는 것이다. "되돌리기"를 누르면 거꾸로 지워진다 |
| 모임 홈 | 응답 수와 진행 막대가 바뀔 때 숫자가 굴러 올라가고 막대가 늘어난다(15초 폴링으로 값이 바뀔 때). 새로 응답한 사람의 칩이 목록 앞에 끼어든다 |
| 마주의 제안 | 제안 카드 두 장을 옆으로 넘겨 본다. "이유 보기"를 누르면 카드가 그 자리에서 펼쳐지며 사람별 가능 여부와 이동 시간이 나온다. 이동 시간은 막대로 그리고, 펼칠 때 막대가 늘어난다 |
| 마주 얼굴 | 상태에 따라 표정을 바꾼다. 제안을 만드는 동안은 "생각 중" 얼굴이 천천히 눈을 깜빡인다. 확정하면 "기쁨"으로 바뀐다. 움직임은 얼굴 안에서만 일어나고 크기와 자리는 그대로다 |
| 확정 | "이걸로 확정"을 길게 누르는 방식이 아니라 한 번 누르고 확인 시트에서 확정한다. 확정되면 요약 카드가 아래에서 올라오고, 날짜와 역에 도장이 찍히듯 한 번 강조된다. 색종이 효과는 쓰지 않는다 |
| 역 목록 | 역을 고르면 사람별 이동 시간 막대가 그 역 기준으로 다시 늘어나고 줄어든다. 평균과 최대 시간이 함께 바뀐다 |
| 시트 | 재촉 메시지, 공유, 확인 시트는 아래에서 올라온다. 끌어내려 닫을 수 있다 |
| 복사와 공유 | 복사 버튼은 누르면 아이콘이 체크로 바뀌었다가 돌아온다. 토스트는 아래 고정 버튼 위에 뜬다 |
| 불러오는 중 | 빈 스피너 대신 실제 배치와 같은 모양의 뼈대(skeleton)를 보여 준다 |

시간표와 제안 카드의 상호작용은 이 서비스만의 것이라 공들일 자리다. 나머지는 한 가지 규칙으로 통일한다.

### 배치 원칙 (모든 화면)

1. **화면마다 큰 제목 한 줄.** 지금 상태를 문장으로 적는다. 예: "토요일 저녁, 5명이 모여요".
2. **주된 행동은 화면 아래 고정 버튼 하나.** 엄지가 닿는 자리다. 보조 행동은 글자 버튼으로 둔다.
3. **정보는 목록으로.** 카드는 사람이 하나를 골라야 하는 제안처럼 "고를 수 있는 물건"에만 쓴다.
4. **마주는 안내 한 줄 옆 28~32px 얼굴로만.** 화면당 한 번만 나온다. 빈 화면과 오류 화면만 64px까지 허용한다.
5. **AI가 쓴 문장은 표시를 다르게.** 마주 줄에 넣어 사람이 정한 사실(확정 시간, 역)과 구분한다.

### 에셋 (Codex로 생성)

`design/brand-v4/`에 둔다. brand-v3는 지우지 않고 기록으로 남긴다.

| 에셋 | 내용 |
|---|---|
| 로고 | 심볼(마주 얼굴을 줄인 형태), 한글 워드마크, 가로 조합, 세로 조합, 흑백 버전. SVG 원본과 PNG |
| 앱 아이콘과 파비콘 | 심볼 기반, 탠저린 바탕 |
| 마주 2D | 평면 얼굴 다섯 표정: 기본, 생각 중, 기쁨, 미안함, 기다림. 아바타 크기(24~64px)에서 읽히게 |
| 브랜드 아이콘 | 마주, 지하철역, 모이는 지점, 시간 칸 등 Tabler 격자에 맞춘 SVG |
| 빈 화면과 오류 그림 | 평면 일러스트 3~4장. 사진이나 3D가 아닌 2D |
| OG 이미지 틀 | 1200×630. 모임 상태 문장을 크게, 로고는 작게 |

Codex 사용법은 기존 메모를 따른다.
- Codex는 소스(SVG 생성 코드, 토큰, 명세)를 쓰고, 브라우저 렌더는 Codex 밖에서 돌린다.
- 쓰기 권한(`--write`)이 필요하다.
- 용량 오류가 나면 이어서 실행(`--resume-last`)한다.

### 다시 배치할 화면

`/`(첫 화면), `/new/[flow]`(모임 만들기), `/meetings/[id]`(모임 홈), 시간 투표, 최적일정, 제안, 출발지 등록, 역 목록, 요약 카드, 공유 시트와 재촉 시트, OG 이미지, 요약 카드 PNG. 관리자 지표 페이지는 새 토큰만 입히고 배치는 그대로 둔다.

### 진행 방식 (내 판단)

- **한 브랜치에서 갈아끼운다.** 운영에 아직 실제 사용자가 없어서, 화면마다 v3와 v4가 섞인 상태를 배포할 이유가 없다. 디자인 작업은 하나의 기능 브랜치에서 하고 끝에 develop으로 합친다. 그동안 develop과 운영은 v3 그대로다. 옛 토큰 이름(`hongsi`, `forest`, `signal`)과 v3 전용 컴포넌트는 마지막 작업에서 지우고, 남은 참조가 없는지 검색으로 확인한다.
- **토큰 생성 스크립트:** `design/brand-v4/tools/build-tokens.mjs`로 새로 쓴다. v3 스크립트는 기록으로 남긴다. 다크 값은 생성하지 않고, 토큰 이름과 구조만 다크를 나중에 넣을 수 있게 짓는다. 지금 생성되는 `prefers-color-scheme` 블록은 v4에서 사라진다.

### 제안 카드의 마주와 문장 표시 (내 판단)

배치 원칙 4(마주는 화면당 한 번)와 5(AI 문장은 마주 줄에)는 제안 화면에서 부딪힌다. 카드가 두 장이고 카드마다 이유 문장이 있기 때문이다. 이렇게 정한다.

- **마주 얼굴:** 제안 화면에서는 맨 위 안내 줄("두 가지를 골라 봤어요")에만 나온다.
- **카드의 이유 문장:** 얼굴 없이 작은 "마주" 글자 표시를 붙인다. 사람이 정한 사실(확정된 날짜와 역)에는 이 표시가 없다.
- **문장 출처 구분:** 모델이 쓴 문장(`source: "ai"`)과 문장 틀로 바뀐 문장(`source: "rule"`)은 화면에서 구분하지 않는다. 둘 다 숫자 검사를 통과한 문장이고, 사용자에게는 같은 마주의 말이다. 출처는 지금처럼 응답과 로그에만 남는다.

### 데이터가 모자라는 상호작용 (내 판단)

API를 바꾸지 않는 범위에서 처리한다.

- **새 응답자 칩이 끼어드는 연출:** 이전 폴링 결과와 비교해 클라이언트에서 판단한다. 첫 로드에서는 연출하지 않는다.
- **시간 제안 카드의 "이유 보기":** 사람별 이동 시간이 없으니 막대 대신 "가능"과 "어려움"으로 나눈 참여자 칩을 보여 준다. 이동 시간 막대는 장소 제안 카드와 역 목록에서만 쓴다.

### 화면 문구 (내 판단)

화면별 큰 제목과 상태 문구는 빌더가 BRAND.md의 말투 규칙(짧은 해요체, 확인한 사실 먼저, 확정 전에 확정됐다고 말하지 않기)으로 쓴다. 호스트는 화면 시안 단계에서 문구를 함께 검수한다. 문구가 바뀌면 e2e의 텍스트 선택자도 같은 작업에서 고친다.

## 검증

- 기존 단위 테스트와 e2e가 통과한다. 화면 구조가 바뀌어 선택자가 깨지면, 테스트가 확인하던 동작을 같은 의미로 다시 확인하게 고친다. 동작 검사를 빼는 것은 안 된다.
- 글자와 바탕의 대비는 WCAG AA를 지킨다. 토큰 생성 스크립트가 주요 조합의 대비를 계산해 기준 미달이면 실패하게 한다.
- 주요 화면을 휴대폰 폭(375px, 430px)으로 캡처해 실패 조건 목록과 대조한다.
- 로고는 16px 파비콘, 32px 아바타, 1200px OG에서 모두 읽혀야 한다.

## 승인 지점 (호스트 결정)

호스트가 두 번 직접 보고 승인한다. 승인 전에는 다음 단계를 코드로 넣지 않는다.

1. **로고와 마주.** 로고 조합 2~3안과 마주 2D 다섯 표정을 claude.ai 페이지로 보여 준다. 실제 크기(16px 파비콘, 32px 아바타, 앱 아이콘, OG)에 놓은 모습을 함께 보여 준다. 고른 안을 다듬어 확정한 뒤에 앱 아이콘, 파비콘, OG, 빈 화면 그림을 만든다.
2. **화면 배치와 문구.** 토큰과 기본 컴포넌트를 만든 뒤, 주요 화면(첫 화면, 모임 홈, 시간 투표, 제안, 역 목록, 요약 카드)을 실제 크기 시안으로 보여 준다. 화면 문구도 이때 함께 검수한다. 승인한 시안대로 모든 화면을 코드로 옮긴다.

Codex 결과가 실패 조건에 걸리거나 시안 단계에서 거절되면, 이유를 적어 같은 Codex 대화를 이어 다시 만든다. 세 번 다시 해도 안 되면 손으로 SVG를 다듬는다. 어느 쪽인지 시안 페이지에 적는다.
