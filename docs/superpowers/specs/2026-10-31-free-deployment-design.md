# 모여락 무료 배포 설계

작성일: 2026-10-31
상태: 초안 (호스트 검토 대기)

## 1. 왜, 무엇을

리뉴얼 0~2단계가 develop에 머지됐지만 아직 어디에도 배포되지 않았다. 기존 서비스는 내려간 상태이고 옛 DB도 남아 있지 않다. 이 문서는 새 앱(`app/`)을 **매달 0원으로** 운영 환경에 올리는 방법을 정한다.

규모는 한 달에 모임 1~5개다(호스트 확인). 이 규모라면 모든 구성 요소를 무료 플랜 안에서 돌릴 수 있다. 설계의 핵심은 무료 한도를 넘어갈 수 있는 곳마다 **과금 대신 멈추는** 장치를 두는 것이다.

## 2. 목표와 비목표

**목표**
- `https://moyeorak.hyunolike.dev`에서 새 앱이 열린다.
- 매달 비용이 0원이다. 한도를 넘더라도 요금이 나가지 않고 해당 기능만 멈춘다.
- develop에 머지하면 운영에 자동 배포된다. PR마다 미리보기 배포가 생기고, 미리보기는 운영 데이터를 건드리지 않는다.
- 배포 뒤 관리자 지표 페이지로 설계 문서 2장의 지표를 볼 수 있다.

**비목표**
- 옛 서비스 데이터 이전. 옛 DB가 없다. `pnpm migrate:legacy`와 `README`의 "옛 서비스에서 옮겨 오기" 절차는 쓰지 않는다.
- 옛 도메인과 옛 링크 호환. 새 주소를 쓰므로 옛 링크는 열리지 않는다. 옛 참여자 인식(`moyeorak.session` 채택) 코드는 해가 없으니 그대로 둔다.
- 별도의 AI 에이전트 서버, 자체 모델 호스팅, 웹 푸시. 3단계에서 필요해지면 그때 Vercel Cron을 더한다.
- 유료 모니터링, 별도 백업 저장소.

**이렇게 되면 실패다**
- 어느 달에 청구서가 온다.
- PR 미리보기에서 만든 테스트 모임이 운영 DB에 섞인다.
- API 키가 브라우저나 저장소로 새어 나간다.

## 4. 요청 흐름

1. 휴대폰이 `moyeorak.hyunolike.dev`를 조회하면 가비아 DNS의 CNAME이 Vercel을 가리킨다.
2. Vercel CDN이 정적 파일(페이지 번들, 마주 이미지, 글꼴)을 주고, 서버 렌더링과 `/api`는 `sin1` 함수가 처리한다.
3. 함수는 Neon의 **풀링 연결 문자열**로 DB에 접속한다. 서버리스는 인스턴스가 늘었다 줄었다 하므로 직접 연결 대신 Neon 풀러를 쓴다.
4. AI, 이동 시간, 장소 검색은 함수만 부른다. 키는 Vercel 환경 변수에만 있다.

## 5. 배포 흐름

- **운영:** Vercel 프로젝트의 Root Directory는 `app/`, Production Branch는 `develop`이다. 지금처럼 PR을 develop에 머지하면 운영에 배포된다. 문제가 생기면 Vercel의 Instant Rollback으로 이전 배포로 되돌린다.
- **미리보기:** PR 브랜치마다 Vercel 미리보기 배포가 생긴다. 미리보기 환경의 `DATABASE_URL`은 Neon의 `preview` 브랜치를 가리켜 운영 DB와 분리한다. 미리보기는 `MOCK_EXTERNAL=1`로 돌리고 외부 API 키를 넣지 않는다. Google, Kakao, NVIDIA를 전혀 부르지 않으니 미리보기가 무료 한도를 쓰지 않고, 키가 노출될 곳도 줄어든다. 실제 외부 연동은 운영에서만 확인한다.
- **`preview` 브랜치 만들기:** 운영 브랜치에 마이그레이션을 적용한 직후, 실제 사용자가 들어오기 전에 운영 브랜치에서 갈라 만든다. 그러면 스키마와 지하철역만 있고 사용자 데이터는 없다. 나중에 다시 만들 때는 Neon의 "부모에서 초기화"를 쓰지 않는다(운영 데이터가 복사된다). 대신 새 루트 브랜치를 만들고 PostGIS를 켠 뒤 마이그레이션을 적용한다.
- **DB 마이그레이션:** 빌드 때 자동으로 돌리지 않는다. 마이그레이션이 든 PR은 머지 전에 운영 DB의 **직접 연결 문자열**(풀러가 아닌 주소)로 `pnpm db:migrate`를 실행한다. `drizzle.config.ts`는 `DATABASE_URL_TEST`가 있으면 그쪽을 먼저 쓰므로, 운영 마이그레이션 명령은 `DATABASE_URL_TEST`를 비운 셸에서 돌린다(`env -u DATABASE_URL_TEST DATABASE_URL=<직접 주소> pnpm db:migrate`). README에 이 명령을 그대로 적는다. 순서를 사람이 정하는 편이, 실패한 마이그레이션이 배포를 반쯤 망가뜨리는 것보다 안전하다. 마이그레이션은 앞 버전 코드와 함께 돌아가도 깨지지 않게(열 추가 위주) 쓴다는 지금의 관례를 유지한다.
- **되돌리기:** 코드는 Vercel Instant Rollback, 데이터는 Neon 무료 플랜의 복원 기간(6시간) 안에서 시점 복원.

## 6. 돈이 새지 않게 하는 장치

이미 코드에 있는 것: 모임당 AI 호출 40회, 모임당 하루 중간역 새 계산 30회와 1시간 캐시, 장소 검색 24시간 캐시, AI 실패 시 정해 둔 문장으로 대체.

배포 때 새로 거는 것:

1. **앱 전체 월 상한 (코드 변경, 실제 방어선).** 지금 상한은 모임 단위라 모임이 많아지면 합계를 막지 못한다. Google 과금 단위는 행렬 **항목 수**(출발지 × 도착지)이므로, 서울 기준 한 달 동안 모든 모임이 Google에 보낸 항목 수를 세고 상한을 넘으면 새 계산을 하지 않는다. 환경 변수 `GOOGLE_MONTHLY_ELEMENT_CAP`, 기본값 4,000. 대중교통 행렬이 상위 항목(월 무료 5천)으로 과금되더라도 그 아래에 있는 값이다. 상한에 닿으면 지금의 모임 상한과 같은 방식으로 최근 캐시를 주거나 429를 돌려준다. 미리보기는 외부 API를 부르지 않으므로(5장) 이 카운터는 운영 DB 하나에만 있으면 된다. 코드가 보장하는 상한이라, 이것이 0원을 지키는 핵심이다.
2. **Google Cloud 할당량 (보조).** Routes API 요청 할당량을 콘솔에서 낮게 건다. 하루 단위 할당량이 있으면 하루 300 요청, 분당 할당량만 있으면 분당 10 요청으로 건다. 예산 알림(1,000원)도 켠다. 예산 알림은 결제를 막지 못하고 할당량도 월 합계를 정확히 막지 못하므로, 둘 다 1번이 고장 났을 때 알아채기 위한 장치다. 결제를 자동으로 끊는 자동화(예산 알림에서 결제 계정 분리)는 두지 않는다. 1번이 상한을 보장하고, 자동화는 무료 운영 규모에 비해 관리할 것이 많다.
3. **Google API 키 제한.** 키가 Routes API만 호출할 수 있게 API 제한을 건다. 서버에서만 부르므로 HTTP 리퍼러 제한은 걸지 않는다.
4. **NVIDIA.** 결제 수단을 등록하지 않는다. 크레딧이 떨어지면 호출이 실패하고 앱은 정해 둔 문장으로 내려간다.

## 7. 코드와 설정 변경

배포를 위해 저장소에서 바꿀 것은 적다.

- **DB 클라이언트 (`app/src/db/client.ts`).** Neon 풀러(PgBouncer, 트랜잭션 모드)와 맞도록 `postgres()` 옵션을 정한다. 이름 있는 prepared statement를 끄고(`prepare: false`), 서버리스에 맞게 연결 수를 작게 둔다. 테스트와 로컬 동작은 바뀌지 않아야 한다.
- **함수 리전.** `app/vercel.json`에 `regions: ["sin1"]`을 둔다. 대시보드 설정 대신 파일로 두는 이유는 저장소에 기록이 남기 때문이다.
- **미리보기의 사이트 주소 (`app/src/lib/site-url.ts`).** `SITE_URL`이 없을 때 지금은 `http://localhost:3000`으로 떨어진다. Vercel이 주는 `VERCEL_URL`이 있으면 그 주소를 쓰게 해서, 미리보기 배포의 링크 미리보기와 요약 카드 링크가 미리보기 주소를 가리키게 한다. 운영은 `SITE_URL`을 명시한다.
- **앱 전체 월 상한** (6장 1번).
- **Hobby 한도 확인.** 구현 전에 Vercel 문서로 Hobby의 함수 최대 실행 시간과 기본값, `sin1` 리전 선택 가능 여부, 함수 번들 크기 한도를 확인한다. 2026년 10월 기준 문서는 Hobby 함수 최대 300초라고 적고 있다. 기본값이 그보다 짧으면, AI를 부르는 라우트(`schedule/parse`, `suggestions`, `nudge`)와 이미지 라우트(`opengraph-image`, `summary/image`)에 `export const maxDuration`을 명시한다. 이미지 라우트는 Pretendard 글꼴 파일을 함께 싣으므로 번들 크기도 본다.
- **문서 (`app/README.md`).** "배포 체크리스트"를 이 설계의 절차로 바꾸고, "옛 서비스에서 옮겨 오기"는 옛 DB가 없어 쓰지 않는다고 표시한다. 환경 변수 표에 `GOOGLE_MONTHLY_ELEMENT_CAP`을 더한다. 운영 마이그레이션 명령(5장)을 적는다.

키, 결제, 계정이 필요한 단계는 호스트가 직접 한다. 저장소 변경과 확인은 Claude가 맡는다.

## 9. 위험과 대응

| 위험 | 대응 |
|---|---|
| NVIDIA 무료 크레딧이 1회성이라 언젠가 끝난다 | AI 기능이 꺼지고 정해 둔 문장과 직접 칠하기로 동작. 관리자 지표의 AI 사용량 표에서 실패가 늘면 알 수 있다. 그때 다른 무료 OpenAI 호환 엔드포인트로 `NVIDIA_BASE_URL`과 키를 바꾸는 길이 있다 |
| Google 대중교통 행렬이 기본 항목이 아닌 상위 항목으로 과금된다 | 상위 항목도 월 무료 건수(5천)가 있고, 앱 전체 월 상한 4,000건이 그 아래에서 멈춘다 |
| Neon이 잠들어 있다가 깨는 첫 요청이 느리다 | 1초 안팎. 이 규모에서는 받아들인다. 깨우기용 주기 호출은 컴퓨트를 쓰므로 하지 않는다 |
| Vercel Hobby 한도 초과로 사이트가 멈춘다 | 이 규모로는 닿기 어렵다. 닿으면 과금 없이 멈추고, 그때 원인(봇 트래픽 등)을 본다 |
| 미리보기 배포 주소가 외부에 노출되어 미리보기 DB에 쓰레기 데이터가 쌓인다 | 미리보기는 외부 API를 부르지 않으니 비용은 생기지 않는다. 브랜치는 5장의 방법으로 다시 만들 수 있다. Vercel의 미리보기 보호(로그인 보호)가 켜져 있으면 카카오톡 미리보기 수집기도 막히므로, 링크 미리보기 확인은 운영에서만 한다 |
| `.dev` HSTS 때문에 인증서가 나오기 전에는 접속이 안 된다 | 가비아 CNAME을 넣고 Vercel이 인증서를 발급할 때까지 몇 분 기다린다. 절차 8단계에서 확인한다 |

## 10. 만드는 사람에게 맡기는 것

- `postgres()` 옵션의 정확한 값(연결 수, 유휴 시간)과 그 근거. 테스트 DB와 로컬에서도 같은 옵션을 써도 되는지 판단.
- 앱 전체 월 상한의 카운터를 어디에 둘지(기존 `external_cache`에 월 단위 행, 또는 작은 테이블과 마이그레이션 0004)와 동시 요청 때 상한을 조금 넘는 것을 허용할지. 지금의 AI 상한은 잠금 없이 한두 번 넘는 것을 허용한다.
- `VERCEL_URL` 사용을 미리보기에만 한정할지(`VERCEL_ENV`로 구분), 운영에서도 `SITE_URL`이 없을 때 쓸지.
- README 문구.

## 11. 이 문서에서 제가 정한 것

호스트가 정한 것은 무료 운영, 월 1~5개 규모, `hyunolike.dev` 서브도메인 사용, 가비아 DNS다. 나머지는 제가 정했다.

- 서브도메인 이름 `moyeorak`
- Vercel과 Neon을 쓰는 것(리뉴얼 설계 4.8의 선택을 유지)과 둘 다 싱가포르에 두는 것
- Production Branch를 `develop`으로 두는 것(지금 저장소에서 PR이 develop으로 머지되므로)
- 미리보기용 Neon 브랜치를 따로 두고, 미리보기는 외부 API 없이 `MOCK_EXTERNAL=1`로 돌리는 것
- 마이그레이션을 빌드에 넣지 않고 손으로 실행하는 것
- Google 사용량을 코드의 월 항목 상한(4,000건)으로 막고, 콘솔 할당량과 예산 알림은 보조로만 두는 것. 결제 자동 차단 자동화는 두지 않는 것
- 운영 확인용 모임을 확인 뒤 지우는 것
- 별도 백업과 유료 모니터링을 두지 않는 것
