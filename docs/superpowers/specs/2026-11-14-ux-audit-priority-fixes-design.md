# UI·UX 감사 우선 수정

2026-11-14 배포본 감사에서 재현한 네 가지 문제를 고친다. 사용자가 감사 결과와 수정 순서를 보고 진행을 요청했다. 기존 브랜치의 미커밋 작업은 포함하지 않는다.

## 목표와 범위

- 시간 확정은 성공했을 때만 다음 단계로 간다. 실패 시 같은 선택과 확인 시트에 오류를 표시하고 다시 시도할 수 있다. 다른 기기가 먼저 확정한 409는 모임 홈에서 결과를 확인한다. 후보가 없으면 확정이나 장소 이동을 제시하지 않는다.
- 장소 검색은 같은 검색어를 다시 제출해도 새 요청을 보낸다. 공백 제출과 같은 요청의 중복 실행은 막고 다른 검색어는 그대로 검색한다.
- 다른 제안 보기는 후보를 보존하며 다음 카드로 이동하고 마지막에서 처음으로 돌아간다. 후보가 하나면 다음 카드 버튼은 숨긴다. 현재 제안을 거절하는 동작은 별도의 이 제안 제외 버튼으로 명시한다. 확정은 현재 보이는 후보에 적용하고 처리 중에는 관련 버튼을 잠근다.
- 확정 도장은 모임 이름 행의 독립 영역에 둬서 320px에서도 날짜와 겹치지 않게 한다. 저장 액션의 짧은 화면 문구는 이미지 저장으로 쓰되 접근성 이름과 기존 다운로드 기능을 유지한다.

## 접근 방식

기존의 Next.js, React, TanStack Query, Tailwind와 컴포넌트를 그대로 사용한다. 에러 처리는 성공 콜백과 실패 콜백을 분리하고 기존 확인 시트에 오류 영역을 추가한다. 검색은 같은 검색어일 때 refetch를 사용한다. 카드 이동은 클라이언트 선택과 스크롤만 변경하며 서버 거절 API는 명시적인 제외에서만 호출한다.

제안 버튼 이름만 제외로 바꾸는 방법은 비교 동작을 제공하지 못한다. 거절 API 자체를 없애는 방법은 기존 후보 제외 기능을 잃는다. 따라서 비교와 제외를 분리하는 방식을 구현자의 판단으로 선택한다. 도장도 글자를 줄이거나 날짜를 잘라 맞추지 않고 실제 레이아웃에서 공간을 확보한다.

## 제약과 검증

새 의존성, 서버 API, DB 스키마, 브랜드 색과 서체는 변경하지 않는다. 나머지 감사 항목과 자연어 입력 실패 원인은 후속 범위다. 로컬 테스트와 모의 외부 응답을 사용하며 검증 중 운영 모임을 수정하지 않는다.

실패→성공 재시도, 409, 후보 없음, 검색어 변경, 중복 제출, 다음 카드 반복 이동, 한 후보, 제외 후 선택 변경을 회귀 테스트로 확인한다. 320·390·480px 카드, 장소만 카드, 긴 날짜와 이름은 실제 브라우저에서 확인한다.
